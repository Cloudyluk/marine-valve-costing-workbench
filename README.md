# 船用低温阀门成本核算工作台

可部署到 GitHub Pages 的静态成本核算网页，包含两个视图：

- **型号成本**：产品型号与成本版本的标准材料、人工、外协质量、制造费用、单位完全成本和建议报价。
- **订单执行**：订单继承型号成本版本后的标准/实际成本、成本差异、毛利和版本切换留痕。

## 本地运行

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
```

## CSV 导入

点击页面右上角“导入 CSV”。它读取 UTF-8 编码的型号成本版本 CSV，并在浏览器会话内更新目录；校验失败不会覆盖当前数据。模板见 [`public/产品成本版本导入模板.csv`](public/产品成本版本导入模板.csv)。

必填列：`产品型号`、`成本版本`、`状态`、`材料成本`、`直接人工`、`外协与质量`、`制造费用`、`目标毛利率`。毛利率可填写 `18%` 或 `0.18`。

## 飞书多维表结构

建立并关联以下 9 张表：

1. 产品成本版本（主表）：型号、版本、状态、材料/人工/外协质量/制造费用汇总、完全成本、目标毛利率、建议报价。
2. BOM材料明细：关联产品成本版本，记录物料、用量、损耗、单价及材料成本。
3. 工艺与人工：关联产品成本版本，记录工时、人工工价、人工成本和设备成本。
4. 外协与质量成本：关联产品成本版本，记录外协、低温试验、无损检测和船级社费用。
5. 制造费用分摊：关联产品成本版本，记录分配基础、费率和金额。
6. 成本变更记录：记录型号成本版本的设计、材料和工艺变动。
7. 生产订单：关联初始及当前产品成本版本，记录数量、标准/实际总成本、销售收入与订单毛利。
8. 订单实际成本明细：关联生产订单，按材料、人工、外协质量和制造费用记录标准/实际差异。
9. 订单版本变更记录：关联订单与新旧成本版本，记录切换原因、影响金额、时间、操作者与审批状态。

主表公式口径：`单位完全成本 = 材料成本 + 直接人工 + 外协与质量 + 制造费用`；`建议报价 = 单位完全成本 ÷ (1 - 目标毛利率)`。订单应永久保留初始成本版本；即使切换当前版本，也不能覆盖历史标准。

## 发布到 GitHub Pages

1. 在 GitHub 新建一个空仓库，例如 `marine-cryogenic-valve-costing`。
2. 将本项目推送到该仓库的 `main` 分支。
3. 在仓库 **Settings → Pages** 中，将 Source 选择为 **GitHub Actions**。
4. 推送后等待 “Deploy GitHub Pages” 工作流完成，即可通过其输出的网址访问。

工作流会自动使用仓库名称作为页面路径，无需手工修改 `base` 配置。
